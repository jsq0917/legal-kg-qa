## 4. 819 与 814 那 5 条差在哪（已查实）

**结论：819 = 814 条规则边 + 5 条 `provenance=manual` 人工语义边。不是数据不一致。**

证据链：

1. `data/graph/stats.json`：`DEFINES = 819`，`defines_by_provenance = {rule: 5018, manual: 5}`。
2. `data/extracted/mentions_typed_stats.json`：`rule_total = 5018`，`manual_total = 5`；实测 `mentions_typed.jsonl` 中 `DEFINES` 819 条的 provenance 分布为 `rule 814 / manual 5`。

这 5 条来自 `data/lexicon/manual_mentions.jsonl`，逐条写明了理由：

## 6. 对图路检索的预期影响（区分实测与预期）

**已实测（默认 819 图，`data/eval_out/retrieval.json`，n=60）**：

| 模式 | R@5 | 路径准确率 | 中位延迟 |

| 纯图 | **0.4417** | 0.5694 | 131.8 ms |
| 混合 | 0.7556 | 0.5694 | 395.7 ms |

> **2026-10-31 重建后重测**（`networkx` + CPU + `--no-llm`，n=60，结果另存 `retrieval_post_rebuild.json`）：
> graph R@5 **仍为 0.4417**，all@5 0.2333，path_recall 0.5694，by_hop 0.45 / 0.425 / 0.45，逐条 recall 变化为 0
> （仅 2 条 top5 排序变化）；中位延迟 301.5 ms 是 CPU 导致，与旧 131.8 ms 不可比。
> 结论：默认图口径由 819 降到 710 后，图路召回未下降，也未提升——**两个文件分开引用，不可混用**。
>
> **吸收 `m` 补边后再次重测**（同栈，`retrieval_post_m_rebuild.json`）：graph R@5 **0.4389**（−0.0028），
> all@5 0.2167（−0.0167），path_recall 0.5694，by_hop 0.4667 / 0.4417 / **0.35**；60 条中 4 条变动（2 升 2 降），
> 在抽样噪声内，但 `cross_law` 桶 −0.10 属方向性风险，待 n 复核。

**严口径的预期（尚未实测，n 未做）**：

- 图路候选池**不会消失**：`__001__networkx_store.py` 的 `_concept_to_articles` 同时收录 `DEFINES` 与 `REFERS_TO`，只是 `REFERS_TO` 按 0.45 降权。因此严口径的实际效果是**把 154 条边从高置信 DEFINES 降级为低置信 REFERS_TO**，主要影响 top-5 排序与置信度，不是删掉候选。
- 静态代理：gold_200 的 116 个概念里，DEFINES 覆盖 54→44；10 个概念（`fault_liability / minimum_wage_standard / liquidated_damages_civil / minimum_wage / liquidated_damages / trade_secret / part_time_wage_settlement / labor_relationship / arbitration / contract_performance`）失去全部 DEFINES 高置信边；154 条丢弃边里 42 条落在金标概念上。
- **结论只能是预期**：严口径下 graph R@5 大概率下降，但降幅必须等 n（PPR/2-hop）与 rev 评测才能给数；本卡不编造实测值。
