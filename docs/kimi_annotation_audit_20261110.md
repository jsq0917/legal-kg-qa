## 3. 盲性核验

### 3.1 没有泄漏的字段

`batch_input_211.txt` 每条只有五项：`case_id / 概念名 / 条文（法名+条号+标题）/ 偏移 / 原文`。
对 `provenance / cue / matched_alias / confidence / defines_score / window / 规则 / 别名 / 置信` 的全文件检索命中数为 **0**。
两份 prompt 只包含判定规则、输出格式和一条 `DEMO-02` 格式示例，**没有逐条答案、没有本批任何 `case_id` 的预判**。

### 3.2 三处残余提示（不构成答案泄漏，但会影响结果解释）

1. **“概念名一定在原文中原样出现过至少一次”**：这句话对 `pending_semantic` 桶是事实，但它同时**取消了“概念未出现/只是别名”这个选项**。如果源边其实是别名误配，模型也无法判出来。
2. **给出精确字符偏移**：模型不需要自己找概念，降低了“定位错误”这一类失误，但也让“复合词内”判定更容易被偏移引导。
3. **`?` 的预期上限写成“不超过 21 条”**：这是一个**偏向二分类的先验**。实际 `? = 0`，与这个先验一致；不能把 0 条 `?` 解释成“211 条都毫无歧义”。

另外，条文编号/法名是可见的（如 `lcl#23` 竞业限制），模型可能调用参数里的法律先验；这是任务本身的可见信息，不是 `provenance` 或规则名泄漏。

### 3.3 是否执行了 prompt 建议的 20 条对齐

`prompt_defines_kimi_k31pro_v2.md` 第 241 行建议“先跑 BL-0001~BL-0020，逐条人工看一遍，再放开全量”。从产物无法判断这一步是否真的做过。**如果没有做，批量版的判定惯性风险更高**，这也是下面要抽检的原因之一。

### 3.4 批次元数据缺口

原始输出没有记录模型快照、`temperature`、`top_p`、调用时间或 API 返回的 usage。文件只能按命名记为 **Kimi-K3.1-Pro**，**无法保证重新调用能得到同一批输出**。这不妨碍把它当“一次性 LLM 预判”使用，但妨碍把它当可复现的金标；写报告时要连同这一点一起交代。

## 4. 质量体检

### 4.1 判定分布

| 维度 | 分布 |
|---|---|
| 判定 | 成立 **53（25.12%）** / 不成立 **158（74.88%）** / 无法判断 **0** |
| 依据 | S（主语位规制）**53** / N **158** / D（定义式）**0** |
| 句法角色（全部） | 宾语 49 / 定语 48 / 主语 36 / 复合词内 32 / 主语中心语 19 / 其他 15 / 介词宾语 12 |
| 成立者的角色 | 主语 34 / 主语中心语 19；**其他角色 0 条成立** |
| 不成立者的角色 | 宾语 49 / 定语 48 / 复合词内 32 / 其他 15 / 介词宾语 12 / 主语 2 |
| 平均判定位置漂移 | 前 60 条成立率 26.7% / 中段 25.0%、26.7% / 末段 19.4%；前半 22.6% vs 后半 27.4% |
| 最长连续同判 | **14 条连续「不成立」**（BL-0030–BL-0043） |

Wilson 95% 区间（仅描述这批判定的内部比例，**不是**语义精度）：

- 成立 53/211 = 25.12%，95% CI **[19.75%, 31.38%]**；
- `evidence` 非原文 4/211 = 1.90%，95% CI [0.74%, 4.77%]。

### 4.2 `evidence` 造假的 4 条（重点）

| case | 概念 / 条文 | 模型 `evidence` | 原文实际 | 性质 |
|---|---|---|---|---|
| BL-0163 | 工资 / `lcl#72` | `最低小时工资标准不得低于` | `……不得低于用人单位所在地人民政府规定的最低小时工资标准` | **语序改写**，不是连续子串 |
| BL-0174 | 债务人 / `cc#395` | `债务人有权处分的下列财产可以抵押` | `债务人或者第三人有权处分的下列财产可以抵押` | **删掉“或者第三人”** |
| BL-0201 | 债务人 / `cc#440` | `债务人有权处分的下列权利可以出质` | `债务人或者第三人有权处分的下列权利可以出质` | 同上 |
| BL-0205 | 第三人 / `cc#614` | `知道或者应当知道第三人对标的物享有权利` | `买受人有确切证据证明第三人对标的物享有权利` | **串用了 `cc#613` 的措辞** |

这 4 条都判「不成立」，标签本身未必错；但 **`evidence` 字段不可信**。尤其 BL-0205 说明模型会把相邻条文的措辞搬过来——这正是批量长上下文最危险的一类错误，不能只用“标签看起来对”掩盖。

### 4.3 退化模式

1. **标签 ≈ 句法角色门控**：53 条成立 = 34 条主语 + 19 条主语中心语；宾语/定语/介词宾语/复合词内/其他 **一条都没成立**。这符合 prompt 的 B 判据，但也意味着模型基本是在做“找主语”，而不是逐条判断“概念是否被正面规制”。
2. **`basis=D` 完全没用**：0 条定义式。`pending_semantic` 的定义就是“机械判据给不出定义式证据”，所以 D=0 有构造上的合理性；但不能据此说“这批边没有定义式边”。
3. **`? = 0`**：prompt 允许最多 21 条，实际一条没用。结合 BL-0174/BL-0201 这类相对从句边界的例子，**模型是在强行二选一**，边界样本很可能被塞进了“不成立”。
4. **概念级一刀切**：`法人` 0/9、`债权` 0/8、`共有` 0/6、`继承` 0/6、`出卖人` 0/4、`占有` 0/4、`收养` 0/4；反过来 `委托人` 4/4 成立、`用人单位` 4/5。抽查的 `法人`/`债权` 例子（BL-0023/0028/0068、BL-0002/0081/0136）确实多为复合词或宾语，**不全是错**；但这种“同一概念全 0/全 1”的形态说明结果是概念刻板印象 + 句法模板的混合，不能当逐条独立语义判断。
5. **批次边界**：原始输出是单批 211 行，**不存在批次拼接导致的边界突变**；但单批 14 条连续同判 + 末段成立率降到 19.4%，说明长上下文内仍有轻微漂移。

### 4.4 逐条抽查（对照原文）

**A. 标签基本站得住，但 evidence 有问题**

- **BL-0205（第三人 / cc#614）**：原文“买受人有确切证据证明第三人对标的物享有权利……”。`第三人` 是“证明”内容从句里的宾语，判 `不成立` 是对的；但 evidence 写成“知道或者应当知道……”（cc#613 的措辞），属于**证据造假**。
- **BL-0163（工资 / lcl#72）**：原文“非全日制用工小时计酬标准不得低于……最低小时工资标准”。`工资` 只在“最低小时工资标准”这个复合词里，判 `不成立` 是对的；evidence 语序被改写。

**B. 边界争议，可能是假阴性**

- **BL-0174（债务人 / cc#395）**：原文“债务人或者第三人有权处分的下列财产可以抵押……”。模型判 `不成立 / 定语`，理由是“主语是下列财产”。但按 prompt 的 B 判据，“债务人……有权处分”本身就是一个带“有权”的规制小句，**判成立也能自圆其说**。这条更适合 `无法判断`，而不是 0。
- **BL-0201（债务人 / cc#440）**：同上，“债务人或者第三人有权处分的下列权利可以出质……”。同样属于相对从句边界，模型强行判 0。
- **BL-0011（劳动者 / lcl#23）**、**BL-0141（定作人 / cc#775）**、**BL-0137（买受人 / cc#614）**：概念是条件小句的主语，主句主语是零指代（“劳动者违反竞业限制约定的，应当……”“定作人提供材料的，应当按照……”）。模型判成立；严格读法可以判不成立。这是**判据边界**，不是明显的模型错误，但它会直接影响 25.1% 这个数。

**C. 质检标记是启发式，不都是真错**

- **BL-0042（买受人 / cc#613）**：模型 `role=主语` 但判 `不成立`，被标“角色与判定矛盾”。原文“买受人订立合同时知道……的，出卖人不承担前条规定的义务”，主句规范的是出卖人，判 0 站得住；**这是质检规则的误报**。
- **BL-0132（出卖人 / cc#595）**：原文是“买卖合同是出卖人转移……的合同”，被定义项是“买卖合同”，不是“出卖人”；判 0 正确，**也是质检误报**。

**D. 成立但属于“效力/范围”而非典型“应当/不得”**

- **BL-0029 地役权 / cc#384**（“地役权消灭”）、**BL-0069 债务 / cc#520**（“债务……消灭”）、**BL-0070 抵押权 / cc#406**（“抵押权不受影响”）、**BL-0016 赠与合同 / cc#658**（“不适用前款规定”）。按 prompt 的 B 判据（范围、效力）可以成立；如果换成更窄的“只有应当/不得/可以”口径，这些会翻成 0。**这说明 25.1% 对判据措辞敏感。**

## 5. 口径定性：只能写「LLM 判定（Kimi）」

### 5.1 不能写成什么

- ❌ “人工盲标 211 条，精度 25.1%”
- ❌ “DEFINES 精度 25.1%”或“DEFINES 精度 75% 不成立”
- ❌ 把 53/211 与 90.4% 字面支撑率、78.7% 严口径混在一起算“综合精度”
- ❌ 用这批结果替代 `data/annotation/defines_pending_211_20261110.xlsx` 的人工盲标

### 5.2 可以写成什么

> “对 211 条 `pending_semantic` 边做了一次 **LLM 预判（Kimi-K3.1-Pro）**：53 条判成立（25.1%，Wilson 95% CI 19.8–31.4%），158 条判不成立，0 条无法判断。该结果**仅作预筛**，不是人工语义精度；其中 4 条 evidence 非原文，说明不能直接采信。真人抽检（40 条）的一致率待补。”

### 5.3 为什么不能用它替代人工盲标

1. **尺子会动**：项目此前已经因为“同一批边换提示词，LLM 判定从 27% 漂到 63%”而放弃 LLM 盲判。这次虽然固定了 prompt、做了 211 条一次性输入，但**判据措辞仍然决定结果**（§4.4 D 的“效力/范围”例子就是证据）。
2. **evidence 不可信**：4/211 非原文，其中 1 条跨条串用；prompt 自己要求“evidence 必须一字不差搜到”，这条硬约束已经被违反。
3. **退化模式**：0 条 `?`、0 条 `D`、标签几乎完全由角色门控；这不是“逐条语义判断”的形态。
4. **覆盖范围**：211 条只是 710 条中的 `pending_semantic` 桶；即使这 211 条全对，也不能推出 710 条整体精度。

### 5.4 与旧口径的关系（保持一致，不自相矛盾）

README §3 现在的写法是：**不引用 LLM 盲判数，只报机械四桶 + 严口径区间**。这次不推翻它，只增加一条**明确标注为 LLM 预判**的辅助信息：

- 机械口径不变：`absent` 68（9.58% 误配）、`derived_only` 47、`pending_semantic` 211、`normal` 384；字面支撑率 90.4%；严口径 559/710 = 78.7%。
- 新增：`pending_semantic` 211 条的 **Kimi 预判**成立 53 条（25.1%）。这不是精度，只是“模型按 B7 判据会放过多少条”。
- **710 条整体语义精度仍然不可报**，因为 `normal`/`derived_only` 没有经过语义判定，`absent` 也不能简单当 0。

## 6. 真人校准方案（40 条，约 1 小时）

### 6.1 抽样设计

文件：`data/annotation/audit_kimi_40_20261110.csv`（脚本 `scripts/make_kimi_audit_sample.py`，seed `20261110`）。

| 层 | 总体 | 抽检数 | 抽法 |
|---|---|---|---|
| Kimi 判「成立」 | 53 | **20** | 按角色分层：主语 12 / 主语中心语 8 |
| Kimi 判「不成立」— 质检异常 | 6 | **6** | 全收（4 证据非原文 + 2 角色矛盾） |
| Kimi 判「不成立」— 其余 | 152 | **14** | 按角色比例：宾语 5 / 定语 4 / 复合词内 3 / 其他 1 / 介词宾语 1 |
| 合计 | 211 | **40** | 行序随机打乱 |

盲性：抽检表只有 `盲标编号 / 概念名 / 条文编号 / 条文标题 / 条文原文 / 偏移 / 概念所在句 / 人工判定 / 备注`，**没有** Kimi 判定、角色、evidence、理由、质检标记，也没有抽样层标识。

### 6.2 怎么填

- 只填「人工判定」（成立 / 不成立 / 无法判断）和「备注」；判不成立或无法判断时写一句依据。
- 判定口径与 `data/annotation/README.md` 第 4 节完全一致，不要临时加严或放宽。
- 40 条 × 1.5 分钟 ≈ 60 分钟；建议一次做完，中途不要回看 Kimi 结果。

### 6.3 怎么算

把抽检结果按 `盲标编号` 与 `kimi_batch_211_parsed.csv` 合并，计算：

| 指标 | 定义 | 用途 |
|---|---|---|
| 总一致率 | 人工与 Kimi 相同的可判条数 / 可判条数 | 主指标 |
| 成立一致率（positive agreement） | Kimi 成立且人工成立 / 人工成立总数 | 防止“把假阳性洗白” |
| 不成立一致率（negative agreement） | Kimi 不成立且人工不成立 / 人工不成立总数 | 防止“把真阳性误杀” |
| Cohen's κ | 两分类一致性（剔除「无法判断」后） | 排除偶然一致 |
| Wilson 95% CI | 对总一致率 | 小样本必须给区间 |

**判读规则（先写死，避免事后挑口径）**：

- 总一致率 ≥ 90% 且成立一致率 ≥ 80%：可以写“Kimi 判定与真人抽检一致率 X%（n=40, Wilson CI …）”，但仍**不能**把 25.1% 直接叫语义精度；只能说“LLM 预判口径下的通过率，经 40 条抽检校准”。
- 总一致率 75%–90%：只能写“弱辅助，一致率 X%”，**不得**用它替换人工盲标结论。
- 总一致率 < 75%：**弃用这批 Kimi 标签**，只保留人工盲标结果；文档里明确写“LLM 预判未通过校准”。
- 无论哪一档，`?` 都要单独报告；不能把「无法判断」算成 0 或 1。

### 6.4 抽检之后能说什么、不能说什么

- 能说：Kimi 与真人在 40 条分层样本上的一致率 / κ；Kimi 的 53 条成立里有多少被真人确认。
- 不能说：710 条整体语义精度；`normal`/`derived_only` 的精度；`pending_semantic` 的精确精度（40 条只能给区间，不能给点估计）。
- 如果一致率很低，**不要**回头改 prompt 再跑一遍直到一致率变高——那是换尺子，不是校准。
