# LexWeave 去人工化方案（已否决 · 仅存档）

> **状态：2026-11-11 用户已否决本方案，未执行、也不在后续改造中实施；文件仅作历史存档，不构成待办。**

> 日期：2026-11-10
> 范围：把评测与结论链路里所有「逐条人工判断」替换掉，目标是**零人工标注也能产出结论**。
> 本文件只做方案，不改代码、不改数据、不改既有文档；落盘为新文档。
> 结论先行：**机械指标可以做到零人工；语义精度不能。** 去人工化的正确目标不是「用模型替代人」，而是**把结论分成三类：机械可验证、多模型一致、不可给真值**，并把第三类从达标口径和简历里删掉。

## 0. 先定义清楚：什么叫「人工环节」

本方案把人工参与分成四种，只有前两种是这次要处理的：

| 类型 | 例子 | 是否算「人工标注」 | 处理 |
|---|---|---|---|
| ① 逐条人工判定 | 金标必要性票、211 条 DEFINES 盲标、100 条抽检 | 是 | 必须替换/删除 |
| ② 人工构造真值 | 200 条场景+概念链、107 题条文映射修正、59 条金标路径边、5 条人工补边 | 是（构造型） | 必须替换/降级/删除 |
| ③ 人工编写规则/代码/测试 | 建边正则、五道闸、B4/B5 脚本用例 | 否 | 保留；但要说明规则本身是人设计的先验 |
| ④ 人工选择超参/模型 | 路由阈值、topK、融合权重、reranker 选型 | 否（但会引入调参偏差） | 改为预注册网格/嵌套验证，或固定默认值并报敏感性 |

**关键区分**：把规则写成代码，不等于零人工；但它是**一次性、可复查、可 diff** 的人工设计，不是逐条标注。真正的硬边界在①和②。

## 2. 逐条替代方案

### 2.0 前置项（必须先做，否则后面全是空中楼阁）

**P0：来源审计，不产生新指标，1–2 天，0 API。**

必须先解决三处冲突，否则「去人工化」会把错误来源洗得更干净：

1. **H7 的 100 条标签**：`defines_human_precision.json` 说是「本人 100/100 人工判定」，`defines_human_labels.provenance.json` 说是「AI agent，100/100 模型完成，INVALID_AS_HUMAN」。两者不可能同时为真。
   - 处理建议：以**更具体、带方法说明的 provenance 文件**为准，把 0.49 重新归类为「LLM 判定」；在 README/简历里删除「人工精度 0.49」。
   - 如果用户确认确实是本人填的，则反过来修正 provenance 文件，并保留 0.49 为「单人人判、非双盲」。**这件事只能由用户确认，机器不能裁决。**
2. **H3 的映射修正**：`gold_combos.py` 注释写「人工逐条核对」，`gold_article_review.json` 的 `reviewer` 是 `assistant`，且 `combos_modified=3` 与代码里 107 题/140 条覆盖对不上。处理建议：先把 107/140 的 provenance 说清；零人工方案下统一降级为「单模型/规则复核」，不再写「人工核对」。
3. **H10 的规则依据**：`edge_typing.py`/`test_defines_guard.py` 注释称 100 条人工盲标，但 `defines_blind_review.json` 的 reviewer 是 `llm_blind_2of3`。处理建议：把「人工」改成「LLM 盲判」，或删除该依据，只保留规则自洽性。

> **审批点 1**：H7 的 100 条到底是谁填的？这决定 0.49 是保留、降级还是删除。机器无法替你确认。

### 2.1 A 类｜机械可验证（可以完全自动化，经得起追问）

| ID | 替代改法 | 改动量 | 花钱 | 替代后还能讲什么 |
|---|---|---|---|---|
| H1/H3/H4/H5 | **结构金标**：不再人工给链，改从法条结构里穷举可验证路径：① 显式定义句（「本法所称 X 是指」「X 是……的合同/行为/权利」）；② `CITES` 97 条条文引用链；③ 章/节层级 + 同章条文共现。expected_path 由图的确定性 walk 生成，**不经过任何语义判断** | 新增 1 个 `scripts/build_structural_gold.py` + 1 个 schema；2–4 天 | 0 | 「金标不是人写的，是从法条结构和 CITES 边穷举出来的，任意一条可复算」；但只能报「结构多跳」，不能叫「真实用户问题」 |
| H2 | 删除人工必要性票；改用**结构必要性**：一条条文是否在「定义句/CITES/章节点」上不可缺，由图的入度/出度/路径唯一性决定 | 删除 `pass_a` 依赖；1 天 | 0 | 「必要性是结构定义，不是语义判断」；不能说「法条对问题必要」 |

| H10 | 删除「100 条人工盲标」依据；保留 `audit_defines.py` 的规则自洽性 100/100，并明确「这只证明代码与规则一致」 | 0.5 天 | 0 | 规则自洽性、可复算；不能讲「规则经过人工验证」 |
| H17 | Cypher 改成 `scripts/run_cypher_checks.py`，CI 里跑（Neo4j 不可用时 skip 并明确标注） | 0.5 天 | 0（CI 分钟级） | 「3 条查询有脚本、有 JSON、可重跑」 |
| H15/H16 | 把人工用例改成**脚本化 reviewer / 性质断言**：accept 当且仅当五闸全过；edit 当且仅当引用不在检索范围；reject 当且仅当域外。B4 期望槽位由 utterance 里的正则/词典确定性推导 | 2–3 天 | 0 | 「状态机和槽位逻辑可被确定性测试覆盖」；不能讲「真人复核提升答案」 |
| H12/H13 | 词表不再「人工策划」，改成**语料驱动候选集**：显式定义句 + 章标题 + 高频 n-gram/PMI + 别名共现；概念边由结构规则（同章、定义句、CITES）生成 | 3–5 天 | 0 | 「概念表是从语料确定性抽出来的，可复算」；但概念数会变，不能再拿 281/811 当固定达标数 |
| H14 | 超参用**预注册网格 + 嵌套验证**：在 dev 集上固定搜索空间，测试集只评估一次；或直接冻结默认值并报敏感性 | 1–2 天 | 0 | 「没有按测试集调参」；但搜索空间仍是人选的 |

**A 类的共同代价**：所有依赖「语义真值」的数字都会变，而且新数字通常更小、更不像「多跳问答」。这是诚实的代价。

### 2.2 B 类｜多模型交叉一致（可以自动化，但不能叫准确率）

| ID | 替代改法 | 改动量 | 花钱 | 替代后还能讲什么 |
|---|---|---|---|---|
| H2 | 用 **3 个不同厂商/不同快照的模型**独立判必要性（每模型 2 次、选项顺序打乱），只报：一致率、Fleiss κ、分歧分布、逐条分歧案例 | 1–2 天；新增 `scripts/consensus_label.py` | 3 模型 × 200 题 × ~3 候选 × 2 次 ≈ 3,600 次调用；国内模型约 **¥10–50**，混合国外模型约 **¥100–400** | 「三模型一致率 X%、分歧集中在哪些句式」；**不能**报「必要性准确率」，也不能叫「金标」 |
| H7/H8/H9 | 把 100 条/211 条/40 条统一改成 **3 模型判定 + 一致率**；删除人工校准环节 | 1–2 天 | 211 × 3 × 2 ≈ 1,266 次；约 **¥5–30**（国内）/ **¥50–150**（混合） | 「LLM 判定（多模型）成立率 X%，模型间一致率 Y%」；不能报语义精度，不能替代人工盲标 |
| H3 | 条文映射改成 **3 模型独立选条 + 只保留全一致项**；不一致项不进入金标，单独列「分歧集」 | 1 天 | 107 题 × 3 ≈ 321 次；约 **¥2–10** | 「金标只保留三模型全一致的映射，覆盖率 Z%」；覆盖率会明显下降 |
| H4 | 59 条人工资格边改成 **3 模型判「概念间是否存在 REQUIRES 关系」**，只保留全一致边；不一致边删除 | 1 天 | 约 100 对 × 3 ≈ 300 次；约 **¥2–10** | 「概念边是模型一致推断，不是法律真值」；路径覆盖率会降 |
| H12 | 概念/别名候选由 3 模型抽取，取交集；场景映射由模型生成 + 结构过滤 | 2–3 天 | 281 概念 × 3 ≈ 843 次；约 **¥5–30** | 「概念表是多模型交集」；概念数会变，不能叫「人工策划的领域词表」 |
| H14 | 路由阈值不调，直接报 **模型/规则默认值 + 敏感性曲线**；或让 3 模型对 hop 类型投票，只报一致率 | 1 天 | 0–¥5 | 「路由在结构标签上的表现」；不再报「调参后 0.88」 |

**B 类的红线**：
- 只能叫「模型一致率 / 分歧率 / 共识集」，**不能叫 accuracy、precision、κ（标注者间）**。
- 必须报告**分歧案例**，不能只报一致率。
- 必须固定模型版本与提示词；换模型/换 prompt 就是换尺子，不能只报变高的那次。

### 2.3 C 类｜直接删除该结论（人工不可替代，机器给不出可信数字）

## 3. 机器无法给真值的硬边界

以下 7 条**不要**包装成 A 类或 B 类。可以保留机制、删除结论：

1. **法条对问题的语义必要性**：结构上「可达」不等于「回答这个问题必需」。机器只能给结构路径，不能给必要性。
2. **DEFINES 的「定义 vs 提及」**：B7 的判据本身就是人设计的操作化定义（主语位 + 情态词/正面规制）。换措辞结果就变；机械四桶是代理，多模型一致是共识，都不是语义真值。
3. **概念表的完整性**：没有「正确概念数」。281 是设计选择，不是客观答案；换抽取方法就会变。
4. **人工修正的收益**：没有真人前后对比，就不能说 HITL 提升答案质量；模拟 reviewer 只能证明流程可跑。
5. **标注者间一致性（κ）**：至少需要两个真人。模型-模型一致性不能叫 κ 的替代，它是另一个构念。
6. **真实用户问题分布**：合成题/结构题再可复算，也不代表真实咨询分布；不能拿它报「真实场景准确率」。
7. **法律正确性**：没有律师/法官参与，就不能说答案「法律上正确」；只能说「引用合法、在检索范围内、时间有效、证据逐字」。

## 5. 对求职叙事的影响

### 5.1 会消失的亮点

1. **「人工盲标 / 三票 / κ 0.95」**：这是目前最像「学术严谨」的部分，但 Pass B 是 LLM，100 条 provenance 又冲突。零人工后只能讲「前人工设计 + 多模型一致」，冲击最大。
2. **「DEFINES 710（强语义）」**：去人工化后只能叫「候选边」，语义精度不可报。
3. **「200 条多跳金标」**：人定骨架去掉后，变成结构金标，规模和题型都会变；「真实法律问题」这个卖点减弱。
4. **「人在环提升答案」**：没有真人修正前后对比，只能讲状态机。
5. **「211 条人工盲标」**：本来就没做，Kimi 也不是人；这条必须删。

### 5.2 反而更硬的机械指标

1. **1465 条法条 / 5826 条边 / 97 条 CITES**：可复算，不依赖任何标签。
2. **五道确定性闸门**：引用存在、检索范围、时间有效、证据逐字、低置信转人工——全是可枚举检查。
3. **引用指标拆分**：must-cite 召回、定长精度、超额引用、越界引用；机械可复算。
4. **泄漏 0**：最长公共子串 + 二元组，可复算。
5. **成本/延迟表**：1.30/2.30 次调用、tokens、P50 延迟；真实计量。
6. **CI 不调 LLM、79 个单测、确定性建图**：工程可复现性。
7. **「结论如实」本身**：包括 hybrid 不显著、DEFINES 不达标、B 档负收益；这在面试里比虚高的精度更难得。

### 5.3 建议的新叙事主线

> 「我把一个法律 RAG 项目的评测从『依赖人工金标』改成了『三层证据』：第一层是机械可验证的引用/范围/时间/证据检查；第二层是多模型独立判定，只报一致率和分歧；第三层是明确承认不可给真值的语义精度，直接不报。这样每个留下的数字都能从仓库复算，也不会把模型共识冒充人工标注。」

面试可讲的三个点：

1. **为什么不能把 LLM 判定叫精度**：同一批 100 条，换提示词从 27% 到 63%；这次 Kimi 又有 4/211 evidence 非原文、0 条「无法判断」。所以只报一致率，不报 accuracy。
2. **为什么结构金标更硬**：CITES/定义句/章节点是法条自带的，不依赖人；缺点是只能测结构多跳，不能测真实用户问题——这一点主动承认。
3. **删掉了什么**：删掉 κ、三票、人工盲标、HITL 收益；保留机械指标和负结果。**删得掉，才说明知道每个数字的边界。**

### 5.4 不建议说的话

- 「零人工 = 完全客观」：规则、词表、超参仍是人设计的；零人工只是零逐条标注。
- 「多模型一致 = 准确率」：一致不等于正确，尤其三个模型可能共享同一套法律先验。
- 「结构金标 = 真实用户问题」：不是；它只保证路径可走。
- 「Kimi 25.1% 就是精度」：不是；单模型、4 条 evidence 非原文、0 条无法判断。

## 8. 一句话总结

**零人工标注可以做到，但代价是：把「语义精度」从项目里拿掉，只保留机械可验证的指标和多模型一致率；同时承认结构金标不等于真实用户问题。** 这不是降级，而是把「哪些数字有真值、哪些只是共识」说清楚——对算法岗面试，后者比一个虚高的精度更值钱。
