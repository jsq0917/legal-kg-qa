## 1. 摘要

本报告覆盖一个中文法律知识图谱增强检索系统的六组实验：图谱治理、检索融合、查询路由、抽取与 DPO、推理与量化、安全与 HITL。结论是：文本检索已接近当前金标上限，图谱路是补充而非主力；路由与精排的收益均在统计噪声内；量化能以更低成本维持引用精度。三条最关键数字：混合检索 R@5 **0.7556**（60 条、in-sample），级联路由准确率 **0.7731**（95% CI [0.7192, 0.8231]），DEFINES 机械复核误配率 **9.58%**（68/710）。三者都不是达标结论，报告在正文逐项给出区间、样本量与失败记录。

## 2. 问题与范围

法律问答的难点不在“生成一段像法条的话”，而在“找对条文、说清依据、承认不知道”。本项目以民法典、劳动法、劳动合同法三部法律为语料，构建 Article–Concept–Scenario 三层图谱，并围绕三个可度量任务展开：给定问题检索必需条文（R@5）、判断问题复杂度以选择检索档位（三分类路由）、从条文抽取实体与关系（strict F1）。服务侧另有引用闸门、注入防护与人工挂起（HITL）。

本文覆盖：图谱口径治理与重建、文本/图/混合检索与精排、规则+语义+LLM 级联路由、0.5B/1.5B/3B 抽取与 DPO、vLLM/SGLang 推理与量化、注入防护与 HITL。

**主链与离线实验的边界**：应用主链（`app/` + API/UI）只包含检索、路由、编排、闸门、HITL 与错误治理，默认通过 OpenAI 兼容端点调用托管模型；抽取模型训练、DPO 偏好对齐、vLLM/SGLang 推理与量化都在实验仓库 `work/` 下离线完成，**不作为服务依赖，也不在请求路径上运行**。本文第 5.4、5.5 节属于离线实验，引用时不要写成「线上系统用了 DPO/vLLM」。本文不覆盖：LLM 全量重跑消融、GPU 环境精排延迟、超过 400 条金标的 5pt 级差异判定、端到端答案质量的大规模人工评分、多租户与线上并发容量。所有实验的样本量都不足以支撑“稳定达标”的表述，正文只报点估计、区间与方向。

## 3. 系统架构

系统按“语料→图谱→检索→抽取→服务→评测”分层，每层都有可单独复算的产物。

分层的好处是故障可归因：检索差可以拆成“链接错、图结构弱、排序错”三段；抽取差可以拆成“边判据、词表、训练目标”三段。后续所有实验都按这个拆法报告，避免把系统级问题写成单点原因。选图谱而非纯向量的理由是可解释：每条边能回到条文偏移，答案可以给“概念→条文”的路径；代价是图谱精度直接成为召回上限，这也是后文把边复核放在第一位的原因。

## 4. 口径与评测方法

**先定口径，再谈数字。** 本项目最先做的不是调模型，而是把“什么算对”写成可机械复核的规则，否则后续每个实验都会换一把尺子。

**机械复核四桶。** DEFINES 边按概念串是否在条文原文中出现、以什么形态出现、是否落在定义式或分句主语位，分为四类：`absent`（完全不出现）、`derived_only`（仅派生形式出现）、`pending_semantic`（字面出现但无定义式/主语位机械证据）、`normal`（机械证据成立）。当前 710 条 DEFINES 的分布是 absent 68、derived_only 47、pending_semantic 211、normal 384，误配率 9.58%（68/710；只算规则边 63/705 = 8.94%）。清洗前同一口径的 absent 占比是 19.9%。`pending_semantic` 一律标注“待语义判定”，既不计入误配，也不当成人工结论；本项目的精度只走机械复核，不引用标注口径的数值。四桶里 `derived_only` 指只出现“权利人/义务人”这类派生形态，`normal` 才要求落在定义式或分句主语位；这条界线保证不同轮次复核可以逐条对齐。

**金标构造与一致性。** 金标共 200 条，跳数分布 two_hop 100 / three_hop 66 / cross_law 34。
构造分两步：**Pass A** 由项目作者逐条给定场景、概念链与意图（人给定的骨架）；
**Pass B** 由 LLM 在「题面 + 候选条文（含同法干扰项）」上独立判必要性，跑两遍取多数票。
报告中的 κ 0.9473 / 0.9329 / 0.9856 是 **Pass A 骨架 vs Pass B 模型判读**的一致度与两次 Pass B 的稳定性，
**不是双人独立盲标，也不是标注者间一致性**；条文级 Pass B 与锁定条文用的精排模型相关，κ 会被抬高。
条文层必要性通过 173/200。金标与 A1 test 的条文交集为 0，成句照抄 0/200，`gold_report.json` 的 `leakage_fail=0`。
数据来源、标注主体、调参历史与已知偏置见 [`docs/data_card.md`](data_card.md)。

**bootstrap 与配对。** 检索与路由用按题重采样的 bootstrap（检索 1000 次、路由 2000 次；融合对照为配对 1000 次，seed=20261031），报告 95% CI 而不是只报点估计。60 条样本下 1 条题约 1.67pp，二项标准误约 0.064，因此小于 2pp 的单点差异一律标注“噪声内”。

**指标定义。** R@5 = |金标必需条文 ∩ top5| / |金标必需条文|；all@5 要求 5 条全中；path_recall = |linker 概念 ∩ 金标概念链| / |链|；cite_precision = |答案引用 ∩ 金标引用| / |答案引用|。检索只看条文命中，不等价于答案正确；生成侧另有引用与接地闸门，本文不把检索指标当端到端质量。

**泄漏与交集检查。** 偏好对构造前做三级匹配（id、归一化文本、5-gram Jaccard≥0.6），从 1250 条训练数据中剔除 3 条污染项（含 1 条完全同文），构对后 500 对与 test60/gold_60/gold_200 交集为 0。消融产物 `ablation.json` 的 `llm_mode=llm`，是重建前的真实 LLM 产物，本轮未重跑；引用时必须带“重建前、未重跑”标签。

## 5. 实验

### 5.1 图谱治理与重建

**设置。** 以三部法律 1,465 条条文、281 个概念、53 个场景建图；DEFINES 采用规则抽取加 5 条人工语义边；概念层补边分机械层与推断层，机械边逐条要求条文原文独立命中，推断边单独存文件并以 `inferred=true` 打标后处理进图。治理方案选“双口径并存”：默认图供召回，严口径只作只读可信子集，不切图。

**结果。**

| 指标 | 数值 | 口径 |
|---|---:|---|
| 节点 / 边 | 1,799 / 5,632 | 当前默认图 `g963749014664` |
| DEFINES | 710（705 规则 + 5 人工） | `data/graph/stats.json` |
| REFERS_TO | 4,119 | 同上 |
| REQUIRES / SPECIAL_OF / APPLIES_TO | 230 / 185 / 291 | 当前图；全部为规则边 |
| `inferred=true` | 0 | 当前图；重建前的 194 条推断边已不进图 |
| 机械复核 | 68/710 = 9.58%（规则 63/705 = 8.94%） | `defines_edges_check_post_rebuild.json` |
| 待语义判定 | 211 | 不计入误配 |
| 严口径（只读） | 559（含人工 564） | `defines_strict_formal.json` |
| 概念层机械边 | 706（291+230+185），2.51 条/概念 | `data/lexicon/stats.json` |

> **历史快照（重建前，已作废）**：1,799 节点 / 5,826 边、REQUIRES 422（含 192 推断）、SPECIAL_OF 187（含 2 推断）、`inferred=true` 194。当前 manifest 与 pkl 均为 5,632 边、REQUIRES 230、`inferred=true` 0，以上旧数字仅用于对照重建前后的变化，不代表当前默认图。

**解释。** 重建把 90 条失去全部字面支撑的别名边真正删除，机械误配率从清洗前的 19.9% 降到 9.58%；剩余 68 条 absent 是“别名仍在词表但正文未字面出现”（承揽 8、企业 5、借款 5、买卖 4 居前），不是新引入的错误。补边使概念层机械边从 577 增至 706，新增 129 条 = APPLIES_TO 93 + REQUIRES 路径直达 24 + 分句依赖 10 + SPECIAL_OF 2；另有 111 条需语义判断的清单不计入达标数，22 条扫描噪声未采纳。**历史快照（重建前）**：当时另有 194 条推断边把双层合计推到 900；推断边敏感性实验显示，2-hop 排除推断边后只掉 0.28pp（0.6111→0.6083），PPR 反而升 0.55pp（0.5917→0.5972），因此图路提升不能归因于补的推断边。当前默认图 `inferred=true` 为 0，上述推断边实验不再对应当前图。重建后图路 R@5 从 0.4417 变为 0.4389（−0.3pt），60 条中 4 条变动（2 升 2 降）。

**局限。** 9.58% 是“字面缺失代理”，不是定义级精度；211 条待语义仍未判定，不能写成“精度已达标”。严口径 559 只做只读复算，未落图，不能当作服务默认。60 条金标上 −0.3pt 不可与噪声区分，cross_law 桶从 0.45 降到 0.35 只是方向性风险（n=10，1 题 10pp）。图见 [fig3_graph_composition.png](figures/fig3_graph_composition.png)。

### 5.2 检索与融合

**设置。** 60 条金标（two_hop 30 / three_hop 20 / cross_law 10），in-sample、无留出集。文本路为 dense+BM25+RRF+精排；图路为实体链接+单跳概念扩展；新增 2-hop 与 PPR 两档；融合对照固定 medium 档、text:graph=0.55:0.45、融合候选 25 条，做 RRF/加权 × 精排/不精排 2×2 四格。oracle 只用金标概念作种子或池内选优，标为不可部署上限。

**结果。**

| 系统 | R@5 | all@5 | 备注 |
|---|---:|---:|---|
| 文本 | 0.7472 | 0.6167 | 中位 411.4 ms |
| 单跳图 | 0.4389 | 0.2167 | 路径准确率 0.5694 |
| 2-hop 图 | 0.6111 | 0.3500 | 中位 224.7 ms |
| PPR 图 | 0.5917 | 0.3500 | 中位 239.2 ms |
| 混合 | 0.7556 | 0.6167 | 中位 395.7 ms |
| 加权 + 精排 | 0.7583 | 0.6000 | +1.11pt、CI 含 0、CPU +10.4 s |
| oracle 候选池 | 0.9194 / 0.9250 | — | RRF / 加权，不可部署 |

图路延迟三值必须分列，不可混用：**131.8 ms**（干净环境）、**301.5 ms**（networkx 离线镜像 + CPU）、**1,045 ms**（同机被抢占）。文本 0.7472 与混合 0.7556 只差 0.84pt；2-hop 0.6111 与 PPR 0.5917 都高于单跳 0.4389，但仍低于文本。分跳看，文本 two_hop 0.8333 / three_hop 0.7000 / cross_law 0.5833，2-hop 图 0.6833 / 0.5667 / 0.4833，图在每一桶都低于文本，跨法差 10pt。

**解释。** 文本路已接近这批金标的上限，混合只补了 0.84pt，远未达到任务设定的 +15pt。图路弱的主因是实体链接：150 个金标概念实例只链上 85 个（0.5694），漏掉的 65 个里有 49 个距种子只有 1 跳；即便用金标概念作种子，图路 oracle 也只有 0.7139，仍低于文本 0.7472。融合的瓶颈不是候选不足：池内 oracle 0.9194/0.9250，52/60、53/60 题金标全在池内，实测精排只拿到 0.7528/0.7583，选优损失约 16.7pp。精排把 top-5 的 80% 位置重排了一遍，净增益 +3.06pp（RRF）/ +5.28pp（加权），两个 CI 都含 0，属无效抖动多于定向纠错。图见 [fig1_b3_retrieval.png](figures/fig1_b3_retrieval.png) 与 [fig4_hybrid_rerank.png](figures/fig4_hybrid_rerank.png)。

**局限。** 全部数字来自同一批 60 条、无留出集，1 条题约 1.67pp，cross_law 仅 10 条（1 条 10pp）。文本基线走 router（medium/complex 混合），四格固定 medium，配对差值只作量级参考。精排延迟是 CPU 实测，200 ms 只是题面口径，本报告没有 GPU 数字。0.7583 与 0.6111 都不是达标结论。

### 5.3 路由

**设置。** 评测集 260 条 = 60 条模板合成 simple + 200 条金标（two_hop 记 medium、three_hop/cross_law 记 complex）。级联为规则快路（高置信 simple/complex 直接短路）→语义层（5 维结构特征 + bge-large-zh 句向量，三分类 LR，margin≥0.20 直接判）→LLM few-shot 兜底。语义层用 5 折 out-of-fold 预测，bootstrap 2000 次。

**结果。**

| 方案 | 260 条 | 金标 200 | 95% CI（260） |
|---|---:|---:|---|
| 规则 | 0.6077 | 0.5550 | [0.5462, 0.6654] |
| 旧 5 维 LR | 0.7385 | 0.66 | [0.6846, 0.7923] |
| 语义层 | 0.7462 | 0.6700 | [0.6923, 0.7962] |
| LLM 全量 | 0.7231 | 0.7100 | [0.6654, 0.7769] |
| 级联（部署） | **0.7731** | **0.7050** | **[0.7192, 0.8231]** |

LLM 兜底触发率 **18.85%**（49/260），单次中位 558 ms、p90 967 ms，摊销约每题 +105 ms。

**解释。** 相对旧 LR +3.5pt、相对规则 +16.5pt，但 0.88 未达到，差 10.7pt。原因不是模型容量：金标 `hop_type` 与 `hops` 有 46/200 不一致，说明 medium/complex 是按标注构造命名，不是题面可读跳数；用一个完美跳数识别器在 gold 上只有 0.835，加上 60 条 simple 满分，整体上界 **0.8731**，仍低于 0.88。级联的错判全部落在 medium↔complex 相邻档，没有任何金标被降到 simple；反事实检索显示复杂题若被强制按 simple 档检索，hybrid R@5 从 0.6917 掉到 0.575（−11.7pt），而升档只多 20–35 ms，因此守卫策略是“宁可升档、不降档”。LLM 的价值只在低置信区间：在语义层 margin<0.20 的 49 条上，LLM 比语义 argmax 高 14.3pt；全量发 LLM 反而把 0.7731 拉回 0.7231。

**局限。** 60 条 simple 是模板合成、与规则守卫同源，1.00 的 simple 召回是结构性结果，不代表真实短问。阈值 0.20 按“触发率<20%”先验定，敏感性表在 0.10–0.25 间波动 ±0.2–0.8pt，不宣称最优。语义层指标用 OOF，部署模型是全量 fit，两者差异未量化。LLM 延迟只在 10 条上测。反事实检索仅 20 条、无 CI，且 simple 档 top_k=3 与跳数效应混在一起。

### 5.4 抽取与 DPO（离线实验，不接入应用主链）

> 本节是 `work/dpo/extract/` 下的离线训练/评测，结论只用于「抽取模型选型」，不描述线上服务。
> 主链的抽取仍是规则 + 词表 + 人工边，见 §3 的「抽取」行。

**设置。** 抽取评测集 test60 为 60 条人工标注（与路由 gold_200 隔离，不混用）。规模对照 0.5B/1.5B/3B 均用 LoRA r=16、2 epoch、seed=42；3B 为 4bit QLoRA。DPO 用 500 对偏好数据：200 对基座负例 + 100 对缺实体 + 100 对关系方向翻转 + 100 对多余实体，β=0.1/0.5 两档；before 为同 session、同 fp16 路径复测的 SFT 0.4887/0.1233。

**结果。**

| 规模 | 实体 strict F1 | 关系 strict F1 | 备注 |
|---|---:|---:|---|
| 0.5B | 0.4825 | 0.0786 | 1250 条训练 |
| 1.5B | 0.4976 | 0.1160 | **850 条子集**，非严格同数据 |
| 3B-4bit | 0.5649 | 0.2032 | 脚注：1/60 与训练同题，剔除后 0.5644/0.2038 |

| 配置 | 实体 F1 | 关系 F1 | 长度（字） | 4-gram 重复 |
|---|---:|---:|---:|---:|
| SFT | 0.4887 | 0.1233 | 194.6 | 0.1515 |
| DPO β=0.1 | 0.5153 | 0.1720 | 248.8 | 0.2240 |
| DPO β=0.5 | 0.5198 | **0.2011** | 223.3 | 0.2039 |

β=0.5 关系 F1 Δ+7.79pt，CI [0.0247, 0.1358] 不含 0；实体 Δ+3.11pt，CI [−0.0052, 0.0650] 不显著。代价是长度 +28.8 字、4-gram 重复 +0.052，CI 均不含 0。

**解释。** 抽取质量随规模单调上升，但 1.5B 只用 850 条，1.5B→3B 的跳幅含数据量差，不能当纯规模效应。DPO 唯一显著收益是关系 F1，实体不显著；LLM judge 胜率 73.7% 看似亮眼，但判官自翻转率 21.7% 且偏好更长输出，与长度膨胀同向，只能作旁证。β=0.1 两项 F1 都不显著，还出现实体>8 占 10%、关系>6 占 5% 的 schema 越界，收益/风险比最差。另有一组四档消融（A/B/C/A_gates）R@5 均为 0.7556，cite_precision 0.3683/0.3864/0.3709/0.3823，差值 CI 全含 0；该产物是重建前 `llm_mode=llm`，本轮未重跑，只能作历史对照。

**局限。** test60 有 1 条与训练同文（train CC-0966 ↔ test CC-0960，完全一致），所有对外数字必须带这条脚注；60 条与 59 条两口径结论一致，但样本量小。偏好对正例来自 A1 train 的蒸馏标签而非人工标注，DPO 本质是在蒸馏分布内做偏好重排。无人类专家判分、单 seed、3B 为 4bit 训练与推理同口径。图见 [fig2_b6_bootstrap.png](figures/fig2_b6_bootstrap.png)。

### 5.5 推理与量化（离线基准，不接入应用主链）

> 本节测的是独立推理引擎的吞吐/量化精度，用于回答「本地部署值不值」，**不改变线上调用方式**：
> 应用主链默认走托管 API，只有显式改 `LLM_BASE_URL` 才会指向本地端点。

**设置。** 单卡 RTX 4060 Laptop 8 GB；vLLM 0.32.0（Triton attention、enforce-eager、gpu-memory-utilization 0.60），SGLang 0.5.23；模型 Qwen2.5-0.5B-Instruct（推理）与 Qwen2.5-1.5B-Instruct（量化抽取）。量化 200 题共用同一份预计算检索上下文，temperature=0；fp16 档 199 题（1 题运行时失败）。

**结果。**

| 项 | 数值 | 口径 |
|---|---:|---|
| vLLM 吞吐 c1/c4/c16 | 70.05 / 275.58 / 697.17 tok/s | **首枪**，0.5B，32 prompts |
| 预热后 c16 | 约 1,040 tok/s | 稳态 |
| fp8 KV 容量 | 2.00×（306,688→613,392 token） | 同后端 |
| fp8 吞吐 / TPOT | −9.6~−12.4% / +10.8~+14.1% | 同后端 |
| fp8 逐字一致 | 0/20（确定性对照 20/20） | 20 题贪心 |
| SGLang c1 / c16 | +26.6% / −65.5%（vs vLLM） | CUDA graph，c16 graph 仅覆盖 bs≤8 |
| 前缀缓存 TTFT | 43.7 ms vs 139.8 ms | SGLang RadixAttention vs vLLM APC |
| q5_K_M | 0.4110 vs fp16 0.4119（Δ+0.02pt，CI 含 0） | 1.3 GB / 2.90 s |
| q4_K_M | 0.3907（Δ−1.92pt，CI 含 0） | 1.2 GB / 2.12 s |
| q8_0 | 0.4296（Δ+1.74pt，CI 含 0） | 1.8 GB / 3.47 s |
| AWQ W4A16 | 0.2944 | 3.62 GB / 5.57 s，单流不占优 |

**解释。** 首枪数字不可引用：同配置 c16 首枪 697.17 tok/s，预热后约 1,040，差距来自调度与 kernel 首次进入；报告一律用预热后数字做加速比，首枪仅作历史留档。fp8 在 0.5B、4096 上下文下只买到容量、买不到速度，KV 池远未成为瓶颈，收益兑现不了；逐字 0/20 说明需要逐字可复现的评测口径不能开 fp8。SGLang 低并发快、高并发崩，直接原因是 decode CUDA graph 只捕到 batch=8，c16 回落实时调度后 TPOT 从 11.4 ms 涨到 38.0 ms；配置对齐（都关 graph）后 SGLang 全面落后。量化上 q5_K_M 支配 fp16：精度差 0.09pt 在 CI 内，显存省 61%、延迟省 44%；q4 是延迟下限；AWQ 在 8 GB 单流下比 Ollama q4 慢 72%，只值得在并发批处理场景再评估。可复现性上，q8 与 fp16 逐字重合 9/20，q5/q4 均 0/20——“精度统计无损”与“输出可复现”是两件事，不能混写。

**局限。** 全部是 0.5B/1.5B 小模型、单卡、32 条请求、短上下文，换 7B 或长上下文结论可能反转。vLLM 与 SGLang 的“同配置”仅指都关 graph、都用 Triton，题源并非同一批原文。Ollama GGUF 与 vLLM AWQ 跨运行时，延迟与显存不可横向拼表。质量只测逐字一致与 cite_precision，未测语义等价。投机解码在本机也不划算：接受率 57.5%，端到端仅 0.88×（44.52 vs 50.56 tok/s），KV 并发容量从 19.27× 降到 9.88×。

### 5.6 安全与 HITL

**设置。** 注入评测分直接指令劫持、间接注入（指令藏在条文里）、越权索取三类；防护只在输入侧做 prompt guard 与数据边界包裹。间接注入样例把“忽略以上全部规则”藏进条文正文，guard 命中后替换为占位符并把整段包进数据边界；越权样例则要求模型输出权限外内容。HITL 用注入时钟模拟 24 h SLA，状态机为 `new → awaiting_review → manual_queue → completed`，每次状态变更写一行审计链（who/when/前后状态哈希），`verify()` 重放校验。

**结果。**

| 项 | 前 | 后 |
|---|---:|---:|
| 总 ASR | 20% | 5% |
| 间接注入 ASR | 75% | 0% |
| 越权索取 | 25% | **25%（未降）** |

HITL：3 条域内挂起-恢复 + 2 条域外拒答；挂起 23 h 恢复 answer 614 字；24.5 h 自动转 `manual_queue` 后恢复 802 字；3 个任务共 8 条审计记录，哈希链连续；状态存 JSON 3/3、无 pkl。

**解释。** 输入侧 guard 能挡指令劫持与间接注入，挡不住越权：它不执行数据权限，模型仍可在允许的文档上下文里被诱导输出不该给的内容。因此对外只能说“这组样本上的残留从 20% 降到 5%”，不能说“注入已解决”。HITL 的关键设计是挂起时只写 user 轮、不写 assistant 轮，避免会话里出现“挂起了一半的假答案”；超时只是换处理人，不删除任务，之后仍可恢复。

**局限。** 攻击集小、单模型、无自适应攻击，5% 不等于安全。审计只覆盖挂起任务生命周期，不记检索与生成。24 h 等待用注入时钟模拟，未做真实时钟长跑；多进程并发写审计的锁未验证。API 未新增 `manual_queue` 端点，明细只能通过 `HitlPipeline.queue()` 取。

## 6. 反例与失败记录

1. **删边/补边后召回下降。** 图路 R@5 从 0.4417 降到 0.4389（−0.3pt），60 条中 4 条变动（2 升 2 降），all@5 从 0.2333 降到 0.2167；cross_law 桶 0.45→0.35。小于二项标准误 0.064，不能据此宣称图路变差，但也不能藏。
2. **精排增益不显著。** 加权+精排 0.7583，相对文本 +1.11pt，CI [−0.0167, 0.0389] 含 0；精排 vs 不精排 +5.28pp，CI 含 0。CPU 单项中位 +10.4 s，top-5 有 82.7% 位置被重排，属“大面积抖动、少量纠错”。
3. **路由未达 0.88。** 级联 0.7731，差 10.7pt；完美跳数识别器上界 0.8731，0.88 在 95% CI 之外。这不是调阈值能解决的，标签口径本身不含该信号。
4. **越权注入未降。** 25%→25%，与总 ASR 20%→5% 形成对照；只报总 ASR 会掩盖短板。
5. **DPO 长度膨胀。** β=0.5 输出 +28.8 字、4-gram 重复 +0.052，CI 均不含 0；关系条数从 1.98 涨到 2.92，下游若要求短输出则是净损失。
6. **fp8 逐字不一致 0/20。** 同一 20 题贪心解码，bf16 两次独立启动 20/20 逐字相同，fp8 与 bf16 逐字 0/20、前 20 字仅 4/20；差异是真实数值扰动，不是采样噪声。
7. **test60 有 1/60 重复。** train CC-0966 与 test CC-0960 文本完全一致；3B 的 0.5649/0.2032 剔除后为 0.5644/0.2038。所有跨任务对比都必须带这条脚注，否则数字会被误读。
8. **2-hop“过线”是 in-sample。** 0.6111 高于任务线 0.58，但参数是在同一批 60 条上选的，CI 下界 0.52，1 条题约 1.67pp；只能算“在这 60 条上过线”，不能当稳定通过。

## 8. 结论与未做

四条结论。第一，文本检索已是当前金标下的主力，混合只多 0.84pt，图谱路是补充；0.7583 与 0.6111 都不是达标结论。第二，路由的提升来自分层与“不降档”守卫，0.88 在当前标签口径下不可达，硬调阈值只会过拟合。第三，抽取质量随规模上升，DPO 只在关系 F1 上有显著收益，代价是长度与重复率。第四，推理侧的可用结论是“q5 保精度省资源、fp8 只买容量、SGLang 高并发不适用”，不是“引擎越快越好”。

未做三件：一是 LLM 全量重跑 ablation（4×60 题，与边界冲突，现有产物为重建前 `llm_mode=llm`）；二是 GPU 环境精排（本报告只有 CPU 10.4 s 实测，200 ms 未测）；三是超过 400 条金标来判定 5pt 级差异（现有 60/200 条样本的 CI 太宽，无法分辨 2–3pt）。这三件不做，报告里相应结论就只能停在“方向性”与“噪声内”。
