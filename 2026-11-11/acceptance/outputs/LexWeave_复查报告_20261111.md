这说明修复就是去掉初验指出的那部分重复计数，没有为了凑数放宽判据。

### 1.4 判据与边界检查

- **排除池边界**：`TEXT_POOL_K=30`（脚本 L48），实际 `text.search(top_k=30, use_rerank=False)` 与 hybrid 内部候选池一致（`__003__hybrid.py` 的 `text.search(top_k=30, use_rerank=False, rrf_k=...)`；`settings.rrf_k` 默认 60，与 `text.search` 默认一致）。没有把 graph top10 误当作文本池排除，也没有只排除 top5。
- **necessary 判据未被放宽**：仍只是 `aid in gold`，没有新增「必须在 hybrid top5」之类条件；同时 `graph_only` 已排除整个 text top30，所以每条 necessary 都确实不可能来自文本候选池。
- **graph_rescued 判据更严，没有放宽**：要求缺失金标**全部**在 graph top5 且**全部**不在 text pool；g95 / g97 因缺失金标同时在 text top30 而不算救回，g157 因 `ll#40` 不在 graph top5、也不在 graph top10 而不算救回。这与产物和 README 的说明一致。
- **g126 / g167 的 `path=[]` 不是路径判据放宽**：产物里的 `path` 取自 `hybrid.items`，这两题的金标没有进入 hybrid top5，所以查不到 item；直接查图路命中可见它们有真实图路径（如 g126 `cc#188`：`limitation_period → cc#188`，coverage 0.5）。这是产物展示字段的取值来源问题，不是 necessary 判据变宽。
- **g191 不在 graph top5 但算 necessary**：它来自 graph top10 候选池并进入 hybrid top5，且不在文本候选池，仍属图路来源；`graph_only` 用 `union(graph_top5, hybrid_top5)`，因此被计入是自洽的。
- **未发现新的重复计数**：307 条全部 `in_text_pool=false`，`in_text_candidates` 与 `in_text_pool` 无一条不一致（旧脚本该字段恒 false 的问题已消失）。

### 1.5 仍需说明的非阻断问题

- `necessary_path_rate` 这个名字容易被读成「路径正确率」，实际是「有图路独有候选的题中，至少含 1 条 necessary 的题占比」（6/119）。数值和产物一致，但命名不够准确，建议在表头写清定义。
- 产物保留了历史别名 `text_failed_graph_recovered`（实际等于 hybrid 补回），`schema_notes` 已明确说明「不等于图路独有救回」。旧复算脚本若继续读该别名仍可能误读，建议下游统一改读 `text_failed_hybrid_recovered`。
