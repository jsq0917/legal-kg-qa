## 1. 调用参数

- **模型**：Kimi-K3.1-Pro
- **参数**：`temperature = 0`，`top_p = 1`，关闭联网与工具调用，不携带任何历史消息
- **粒度**：**一行一次调用**。本表已按概念/条文打散（相邻两行的概念名和条文编号都不同），正是为了防判定惯性；塞进同一会话，模型会开始"找规律"而不是"读条文"

- **顺序**：按 `case_id` 升序跑。不要 shuffle，否则事后对不齐
- **重跑**：单条 JSON 解析失败允许重试 2 次；重试仍失败就记 `PARSE_ERROR` 留空，人工补，**不要**让模型"再想想"

## 2. System Prompt（整段复制；同内容见 `prompt_defines_kimi_k31pro_v2.system.txt`）

```text
你是《中华人民共和国民法典》及配套劳动法律的条文知识图谱 DEFINES 边判定员。你只做一件事：判断给定的一条条文，是否对给定的「概念名」构成【定义】或【正面规制】。

## 输入字段
- concept：待判定的概念名。它一定在条文中原样出现过至少一次（本批数据已由脚本保证），不要去找别名，不要判「概念未出现」。
- article_id / citation：仅用于定位，不参与判定。
- text：条文原文。这是唯一权威文本。
- offsets：概念名在 text 中的 0 起字符偏移，可能有多个，逗号分隔。
- sentences：按「。；换行」切出的、含该概念的句子。可能被截断、可能带 ①②③ 标号，只用于快速定位，不作判定依据。

## 判定流程（按顺序执行，不许跳步）
第 1 步 定位：用 offsets 在 text 中逐处核对概念字符串是否真的起于该偏移。
第 2 步 划界：对每一处出现，看它所在的完整词语。
  若该处只是更长词语的内部构成（如「营利法人」中的「法人」、「按份共有」中的「共有」、「非法人组织」中的「法人」、「债权人」中的「债权」），记为「复合词内」，该处不计为该概念的一次独立出现。
  只有作为独立词语出现，才进入第 3 步。
  若所有出现处都是复合词内，直接判「不成立」，role 填「复合词内」。
第 3 步 切分句：把 text 按「，。；：、（）」切成小句，找到每一处独立出现所在的小句。
第 4 步 定角色：把该小句压缩成「谁 + 做什么」，判断概念能否充当「谁」。
  能充当 → 主语；若概念是「X 的 Y」结构里的中心语 Y 且整个结构作主语 → 主语中心语。
  只能充当动作的承受者 → 宾语。
  位于「对 / 关于 / 就 / 因 / 依照 / 向 / 与 / 由 / 被」之后 → 介词宾语。
  位于「X 的 Y」中修饰 Y → 定语。
  位于「A、B、C」并列中，且并列整体不作主语 → 并列项。
第 5 步 套判据 A / B。
第 6 步 默认不成立：除非你能指出命中 A 或 B 的某一个具体小句，否则一律判「不成立」。
第 7 步 只有落入 C 的三种情形，才判「无法判断」。

## A 定义式 → 成立
条文给出该概念的内涵、外延或构成。典型形式：
- 「X 是指……」「本法所称 X，是指……」
- 「X 是……的合同 / 行为 / 权利 / 组织」
- 「X 包括……」「X 分为……」「X 由……构成」
要求 X 作被定义项（定义句的主语或话题），不要求出现「是指」二字。

## B 主语位正面规制 → 成立
概念（或其同指代「该 X」「其 X」）位于某小句的主语或主语中心语位置，且该小句的谓语直接规定它：
- 应当 / 不得 / 可以 / 有权 / 必须 / 无须 / 不予 做什么；或
- 直接规定它的范围、效力（有效 / 无效 / 不发生效力 / 受法律保护 / 不得对抗）。
「的」字结构判断：「[借款的] 利率 不得违反国家有关规定」——「利率」是中心语、整个结构作主语，算主语中心语，成立；仅作定语的「借款」不算。

## 不成立（多数情况落在这里）
1. 动词宾语：订立 / 解除 / 变更 / 履行 / 转让 / 放弃 / 行使 / 请求 / 主张 X。
2. 介词宾语：「对 / 关于 / 就 / 因 / 依照 / 向 / 与 X」。
3. 并列列举项，且该并列整体不作主语。
4. 定语：「X 的 Y」中 X 修饰 Y。
5. 举例、背景、目的说明；条文真正规范的是别的主体或事项。
6. 概念嵌在更长的复合概念里（见第 2 步）。

## C 无法判断（宁少不多，本批预期不超过 10%）
1. text 明显残缺或被截断，主语与谓语关系无法复原；
2. 同一概念名在同一条中指代两个不同法律对象，且判定结果随之不同；
3. 成立与否取决于条文完全未给出的前提，且你无法用一句话写出稳定理由。
除这三种之外一律二选一。只要你能写出一句可靠的依据（不含「可能 / 似乎 / 也许」），就不许用「无法判断」。

## 硬约束
- 只依据本条记录判定。不引用一般法理、立法目的、常识或其他法条。
- 不推测未给出的信息，不补全原文，不参照其他记录。
- 判「成立」必须落到一个具体小句；找不到就是「不成立」。
- evidence 必须是 text 的连续原文子串（不超过 30 字），不得改写、不得拼接、不得加括号注释或说明性文字。
- 不因条文主题与该概念相关就判成立；不因概念出现在句首就判成立。
- 除单行 JSON 外不输出任何字符：无前言、无解释、无 markdown 代码块围栏。

## 输出格式
单行 JSON，字段与顺序固定：
{"case_id":"...","label":"成立|不成立|无法判断","basis":"定义式|主语位规制|无","role":"主语|主语中心语|宾语|介词宾语|定语|并列项|复合词内|其他","evidence":"...","reason":"..."}
- label=成立 ⇔ basis 为「定义式」或「主语位规制」；label 为「不成立 / 无法判断」⇔ basis 为「无」。
- role：概念在命中小句中的句法角色。判成立时它应为「主语 / 主语中心语」；判不成立时如实填。
- evidence：判成立填命中的小句片段；判不成立填概念实际所在的成分片段。必须是原文子串。
- reason：一句话依据，不超过 40 字，不得出现「可能 / 似乎 / 也许 / 大概 / 倾向于 / 应该是」。
- 不输出 confidence、不输出多行、不输出任何补充字段。

## 输出前自检（默查，不写出来）
1. 我写的 evidence，能一字不差地在 text 里搜到吗？搜不到 → 我在编，重判。
2. 判成立时，把这个概念从那个小句里删掉，小句还站得住吗？还站得住 → 概念不是主语，重判。
3. basis=主语位规制 时，概念真的是「谁做什么」里的「谁」吗？
4. 我是不是因为句首出现、或条文主题相关，就判了成立？
5. 我用了「无法判断」吗？理由确实属于 C 的三种之一吗？不属于就改判。
```

## 5. 常见误判对照（v1 的示例里踩过、以及实测错误分类揭示的）

| 错误写法 | 为什么会错 | 正确做法 |
|---|---|---|
| `evidence` 写「概念作宾语」 | 这是描述不是证据，也无法回溯 | 描述放 `role`，`evidence` 必须是原文子串 |
| 把「营利法人」中的「法人」当作本条对「法人」的规定 | 本批 `standalone_offsets` 只排除 `X人/X权/X物/X方/X者` 后缀，排除不掉前缀型复合词 | 走第 2 步「划界」，记 `role=复合词内` |
| 条文主题与概念高度相关就判成立 | 相关性不是主语位（实测错误里 53% 是角色错） | 概念必须真的在「谁做什么」的「谁」位 |
| 拿不准就填「无法判断」 | 会把盲标信息量冲掉，也让精度虚高 | 能写出一句稳定依据就必须二选一 |
| 凭「这条边本来应该成立」的直觉 | 机械判据已给出 `pending_semantic`，就是缺证据 | 找不到小句就是「不成立」 |
| `reason` 写「可能属于主语位」 | 模糊词等于没判 | 去掉模糊词，或改判 |

另：本表有一对同名同条文的记录（概念名「违约金」、条文 `lcl#22`，两个不同 `concept_id`，对应 `BL-0108` 与 `BL-0131`）。两条输入完全相同，输出必然相同，`role / basis` 也应当一致——**这不是重复错误，不要当成异常处理**。

### 6.2 跑了之后必须做的校验

```python
import json, pandas as pd

SRC  = "data/annotation/defines_pending_211_20261110.csv"
PRED = "data/annotation/kimi_defines_pred_v2.csv"

src = pd.read_csv(SRC, encoding="utf-8-sig", dtype=str)
pred = pd.read_csv(PRED, dtype=str)

LABELS = {"成立", "不成立", "无法判断"}
BASES  = {"定义式", "主语位规制", "无"}
ROLES  = {"主语", "主语中心语", "宾语", "介词宾语", "定语", "并列项", "复合词内", "其他"}

# 1 覆盖与唯一性
assert len(pred) == 211, len(pred)
assert pred["case_id"].is_unique and set(pred["case_id"]) == set(src["盲标编号"])
assert pred["label"].isin(LABELS).all(), pred.loc[~pred["label"].isin(LABELS), "label"].unique()
assert pred["basis"].isin(BASES).all()
assert pred["role"].isin(ROLES).all()

# 2 basis 与 label 自洽
ok = pred.apply(lambda r: (r["label"] == "成立") == (r["basis"] != "无"), axis=1)
assert ok.all(), pred.loc[~ok, ["case_id", "label", "basis"]]

# 3 evidence 必须是原文连续子串（这条能直接抓出编造的证据）
m = src.set_index("盲标编号")["条文原文"].to_dict()
bad = [(r.case_id, r.evidence) for r in pred.itertuples()
       if str(r.evidence) not in m[r.case_id]]
assert not bad, f"evidence 不在原文中：{bad[:5]}"

# 4 分布监控
print(pred["label"].value_counts(normalize=True))       # 无法判断 > 10% 说明 C 被放宽了
print(pred["role"].value_counts())
print(pred["basis"].value_counts())

# 5 复核队列：优先看这几类
queue = pred[(pred["basis"] == "主语位规制") | (pred["label"] == "无法判断")
             | (pred["role"] == "主语中心语")]
queue.to_csv("data/annotation/review_queue_v2.csv", index=False, encoding="utf-8-sig")
print("待复核", len(queue))
```

### 6.3 判读阈值

| 指标 | 阈值 | 超了怎么办 |
|---|---|---|
| `无法判断` 占比 | ≤ 10%（约 21 条） | 提示词 C 段被放宽，收紧后重跑，不要直接采信 |
| `成立` 占比 | 参考机械判据的量级 | 明显偏高（如 > 60%）说明在「看着相关就判成立」，抽 20 条核对 |
| `PARSE_ERROR` | = 0 | 有就单条重试，仍失败转人工 |
| `role=复合词内` 占比 | 观察值 | 明显偏高说明「划界」这步被用过头，抽 10 条核对 |

### 6.4 独立校准（必做）

你完全独立判 20–30 条，判完再看模型结果，算一致率。不一致的逐条看是模型错还是你错——这一步本身就是最好的口径校验，比模型跑得多准更重要。

## 7. 回填注意

- 按 `case_id` 回到源数据，**不要**用「概念名 + 条文编号」，那会撞上 `违约金 / lcl#22` 那一对
- 输出列建议：`盲标编号, concept_id, concept_name, article_id, human_label, note, annotator, annotated_at`
- `human_label` 映射：`成立→1`、`不成立→0`、`无法判断→"?"`
- `annotator` 写 `"LLM(Kimi-K3.1-Pro) 预标 + 本人全量复核"`
- 模型给的 `reason` 可以进 `note`，但要标前缀，例如 `[LLM]` 后面再写你的复核意见
- 不要覆盖 `data/eval_out/` 下任何已有文件，落新文件名

## 8. v1 → v2 改了什么

| # | 改动 | 依据 |
|---|---|---|
| 1 | 加入「默认不成立」的举证责任框架（第 6 步） | 同一批 100 条，模型高估 17 条、低估 3 条，**系统性偏高** |
| 2 | 「划界」提为独立判定步骤 | `build_pending_semantic_kit.py` 的 `standalone_offsets` 只排除 `X人/X权/X物/X方/X者` 后缀，对「营利法人」「非法人组织」「按份共有」这类前缀型复合词无防护 |
| 3 | 输出加 `role` 字段（8 值枚举） | 实测错误分类中 `role_error` 占 53%，没有这个字段无法事后定位错在哪一步 |
| 4 | `evidence` 收紧为「必须是原文连续子串」 | 可程序校验，直接把编造的证据拦下来，不靠人眼看 |
| 5 | 增加「主语中心语」这一档 | 「借款的利率不得违反……」这类「的」字结构，v1 的二分法（主语 / 非主语）会误判成定语 |
| 6 | 明确「概念一定原样出现」，禁止判「概念未出现」 | 本批由脚本断言过 `offsets` 非空，`absent` / `derived_only` 已被排除在 211 条外，v1 的提醒反而会诱导模型乱找别名 |
| 7 | `无法判断` 收紧为三种 + 禁用模糊词 + 10% 阈值 | README §7 要求单独报告条数，口径必须硬 |
| 8 | 质检从 5 条口语建议改成可运行校验 + 复核队列 | v1 的质检全靠人盯，`evidence` 编造根本没有拦截手段 |
| 9 | 示例概念全部换成表外概念（v1 用「法人」作示例，而「法人」在本表出现 9 次） | 避免示例与表内概念撞车产生系统性偏好 |
| 10 | 补「同名同条文」那对记录的说明 | `BL-0108` / `BL-0131` 会被误当成重复错误去排查 |

## 附录：批量调用骨架

```python
import json, time, pandas as pd
from openai import OpenAI

client = OpenAI(base_url="<Kimi 兼容端点>", api_key="<KEY>")
SYSTEM = open("data/annotation/prompt_defines_kimi_k31pro_v2.system.txt", encoding="utf-8").read()

df = pd.read_csv("data/annotation/defines_pending_211_20261110.csv",
                 encoding="utf-8-sig", dtype=str).sort_values("盲标编号")
df = df.head(20)   # 先跑 20 条校准，确认无误再放开全量

out = []
for _, r in df.iterrows():
    user = (
        f"【本条记录】\ncase_id: {r['盲标编号']}\n概念名: {r['概念名']}\n"
        f"条文编号: {r['条文编号']}\n条文标题: {r['条文标题']}\n"
        f"条文原文: {r['条文原文']}\n"
        f"概念出现位置: {r['概念出现位置（0起字符偏移）']}\n"
        f"概念所在句: {r['概念所在句']}\n\n只输出 JSON。"
    )
    rec = {"case_id": r["盲标编号"], "label": "PARSE_ERROR"}
    for attempt in range(3):
        try:
            resp = client.chat.completions.create(
                model="kimi-k3.1-pro", temperature=0, top_p=1,
                messages=[{"role": "system", "content": SYSTEM},
                          {"role": "user", "content": user}],
            )
            txt = resp.choices[0].message.content.strip()
            txt = txt.removeprefix("```json").removeprefix("```").removesuffix("```").strip()
            rec = json.loads(txt)
            break
        except Exception as e:
            rec = {"case_id": r["盲标编号"], "label": "PARSE_ERROR", "raw": str(e)}
            time.sleep(2)
    out.append(rec)

pd.DataFrame(out).to_csv("data/annotation/kimi_defines_pred_v2.csv",
                         index=False, encoding="utf-8-sig")
```

> 一处提醒：`Kimi-K3.1-Pro` 默认开启思考且思考计入输出 token。跑之前确认关闭思考或按含思考的口径估算成本，否则单价会比你预期高一截。
