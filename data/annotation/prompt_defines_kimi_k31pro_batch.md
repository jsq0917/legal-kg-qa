## 1. System Prompt（整段复制，先粘这条）

```text
你是《中华人民共和国民法典》及配套劳动法律的条文知识图谱 DEFINES 边判定员。下面会给出一批待判记录，请逐条独立判定，并且一次性全部输出。

## 输入格式
每条记录以【case_id】开头，包含四项：
- 概念名：待判定的概念。它一定在原文中原样出现过至少一次，不要判「概念未出现」，不要找别名。
- 条文：法名与条号，只用于定位，不参与判定。
- 偏移：概念名在原文中的 0 起字符位置，可能多个，逗号分隔。
- 原文：唯一权威文本。

## 判定流程（每条都完整执行，不许跳步）
第 1 步 定位：用偏移核对概念字符串在原文中的实际位置。
第 2 步 划界：看该处所在的完整词语。若它只是更长词语的内部构成（如「营利法人」中的「法人」、「按份共有」中的「共有」、「非法人组织」中的「法人」、「债权人」中的「债权」），记为「复合词内」，该处不计为该概念的一次独立出现。若所有出现处都是复合词内，直接判 0，role 填「复合词内」。
第 3 步 切分句：按「，。；：、（）」把原文切成小句，定位每一处独立出现所在的小句。
第 4 步 定角色：把该小句压成「谁 + 做什么」，判断概念能否充当「谁」。能 → 主语；是「X 的 Y」的中心语且整个结构作主语 → 主语中心语；只能当动作的承受者 → 宾语；位于「对 / 关于 / 就 / 因 / 依照 / 向 / 与 / 由 / 被」之后 → 介词宾语；在「X 的 Y」中修饰后面的 Y → 定语；在「A、B、C」并列中且并列整体不作主语 → 并列项。
第 5 步 套判据 A / B。
第 6 步 默认不成立：除非能指出命中 A 或 B 的某一个具体小句，否则一律判 0。
第 7 步 只有落入 C 的三种情形，才判 ?。

## A 定义式 → 1
条文给出该概念的内涵、外延或构成：「X 是指……」「X 是……的合同 / 行为 / 权利 / 组织」「X 包括……」「X 分为……」「X 由……构成」。只要求概念作被定义项，不要求出现「是指」二字。

## B 主语位正面规制 → 1
概念（或其同指代「该 X」「其 X」）位于某小句的主语或主语中心语位置，且该小句谓语直接规定它：应当 / 不得 / 可以 / 有权 / 必须 / 无须 / 不予 做什么；或直接规定它的范围、效力（有效 / 无效 / 不发生效力 / 受法律保护 / 不得对抗）。
「的」字结构：「[借款的] 利率 不得违反国家有关规定」中「利率」是主语中心语，算；只作定语的「借款」不算。

## 不成立（多数情况落在这里）
1. 动词宾语：订立 / 解除 / 变更 / 履行 / 转让 / 放弃 / 行使 / 请求 / 主张 X。
2. 介词宾语：对 / 关于 / 就 / 因 / 依照 / 向 / 与 X。
3. 并列列举项，且并列整体不作主语。
4. 定语：「X 的 Y」中 X 修饰 Y。
5. 举例、背景、目的说明；条文真正规范的是别的主体或事项。
6. 概念嵌在更长的复合概念里（见第 2 步）。

## C 无法判断（记 ?，宁少不多，整批预期不超过 21 条）
1. 原文明显残缺或被截断，主语与谓语关系无法复原；
2. 同一概念名在同一条中指代两个不同法律对象，且结论随之不同；
3. 成立与否取决于原文完全未给出的前提，且你写不出一句可靠理由。
除这三种之外一律在 1 与 0 之间二选一。只要你能写出一句不含「可能 / 似乎 / 也许」的依据，就不许用 ?。

## 批量纪律（违反任一条即视为无效输出）
1. 输出行数必须等于输入条数。一条不能少、不能合并、不能拆成两行。
2. 顺序必须与输入完全一致，case_id 原样回填。
3. 每条独立判定。不得参考刚判过的上一行，不得因为前面连续是 0 就跟着给 0，也不得因为同一概念前面判过 1 就沿用。
4. 不输出任何解释、前言、总结、表头、markdown 围栏、空行。
5. 确实判不了的条目也要照常输出一行，label 填 ?。

## 输出格式
每条一行，管道分隔六个字段：
case_id|label|basis|role|evidence|reason
- label：1 = 成立，0 = 不成立，? = 无法判断
- basis：D = 定义式，S = 主语位规制，N = 无。label=1 时必须是 D 或 S；label=0 或 ? 时必须是 N
- role：主语 / 主语中心语 / 宾语 / 介词宾语 / 定语 / 并列项 / 复合词内 / 其他
- evidence：原文中的连续原文子串，不超过 20 字。不得改写、不得拼接、不得加括号注释
- reason：一句话，不超过 25 字。不得出现「可能 / 似乎 / 也许 / 大概 / 倾向于 / 应该是」
示例行（示例数据不在本批之内）：
DEMO-02|1|S|主语|自然人从出生时起到死亡时止|概念作主语，条文直接规定其权利能力

## 输出前自检（默查，不写出来）
1. 我输出的行数，等于输入给的条数吗？
2. 每条的 evidence，都能在对应原文里一字不差地搜到吗？搜不到说明在编，重判。
3. 判 1 的那些条，把概念从那个小句里删掉，小句还站得住吗？站得住说明它不是主语，重判。
4. 我有没有因为连续同类就顺着判？把那几行单独回看一遍。
```

## 2. 输入（直接粘 `batch_input_211.txt` 全文，约 3.2 万字符）

格式如下，`batch_input_211.txt` 已经是这个形状，不用再处理：

```text
【BL-0001】
概念名: 共有
条文: cc#306 中华人民共和国民法典第三百零六条
偏移: 11, 109
原文: 按份共有人转让其享有的共有的不动产或者动产份额的，……

【BL-0002】
概念名: 债权
条文: cc#392 中华人民共和国民法典第三百九十二条
偏移: 4, 61, 103, 129
原文: 被担保的债权既有物的担保又有人的担保的，……
```

刻意去掉了 `概念所在句`：它是从 `。；` 切出来的，经常被截断、带 ①②③ 标号，批量输入里它是纯噪音，还会让模型误把截断后的片段当完整语境。省下的篇幅换 211 条全量一次性输出，更值。

## 3. 拿到输出之后：解析 + 质检

管道格式很好解析，顺手把该做的校验都做了：

```python
import re, pandas as pd

RAW  = "data/annotation/kimi_batch_out.txt"   # 把模型输出整段存成这个文件
SRC  = "data/annotation/defines_pending_211_20261110.csv"

src = pd.read_csv(SRC, encoding="utf-8-sig", dtype=str)
txt = open(RAW, encoding="utf-8").read()

LAB = {"1": "成立", "0": "不成立", "?": "无法判断"}
rows = []
for line in txt.splitlines():
    line = line.strip().strip("`")
    if not line or "|" not in line:
        continue
    p = [x.strip() for x in line.split("|")]
    if len(p) != 6 or not re.fullmatch(r"BL-\d{4}", p[0]):
        continue
    rows.append(dict(zip(["case_id", "label", "basis", "role", "evidence", "reason"], p)))

pred = pd.DataFrame(rows).drop_duplicates("case_id")
print("解析到", len(pred), "条 / 应为 211")

# 1 覆盖率
missing = set(src["盲标编号"]) - set(pred["case_id"])
print("缺失", len(missing), sorted(missing)[:10])

# 2 枚举
assert set(pred["label"]) <= {"1", "0", "?"}, set(pred["label"])
assert set(pred["basis"]) <= {"D", "S", "N"}
assert set(pred["role"]) <= {"主语","主语中心语","宾语","介词宾语","定语","并列项","复合词内","其他"}

# 3 basis 与 label 自洽
bad = pred[((pred["label"] == "1") != pred["basis"].isin(["D", "S"]))]
print("自洽异常", len(bad))

# 4 evidence 必须是原文子串（抓编造）
m = src.set_index("盲标编号")["条文原文"].to_dict()
notfound = [(r.case_id, r.evidence) for r in pred.itertuples()
            if r.evidence not in m[r.case_id]]
print("evidence 不在原文中：", len(notfound), notfound[:5])

# 5 分布
print(pred["label"].map(LAB).value_counts(normalize=True))
print(pred["role"].value_counts())

out = pred.assign(人工判定=pred["label"].map(LAB))[["case_id", "人工判定", "role", "evidence", "reason"]]
out.columns = ["盲标编号", "人工判定", "句法角色", "evidence", "reason"]
out.to_csv("data/annotation/kimi_batch_parsed.csv", index=False, encoding="utf-8-sig")
print("已写出 kimi_batch_parsed.csv")
```

判读阈值（和 v2 一致）：

| 指标 | 阈值 | 超了怎么办 |
|---|---|---|
| 解析条数 | = 211 | 少了就补那一批，别用模型"再想想"补 |
| `?` 占比 | ≤ 10%（21 条） | C 段被放宽，收紧重跑 |
| `1` 占比 | 明显高于机械判据量级 | 在"看着相关就判成立"，抽 20 条核对 |
| evidence 不在原文 | = 0 | 有就说明在编证据，该批全废重跑 |

如果 `evidence 不在原文` 不是 0，别逐条改——那说明这一批整体在编，重跑比修补便宜。

## 4. 为什么批量版可以跟单条版同口径

单条调用的理由是"防判定惯性"。这张表本身已经做过 `decluster`（相邻两行的概念名和条文编号都不相同），所以同一条消息里 211 条并不会形成"同一概念连续出现"的诱导。真正的风险是模型偷懒：连续输出 0 之后开始整段抄 0。

所以批量版多了两条单条版没有的东西：一是 **批量纪律第 3 条**（明令禁止沿用邻行结论），二是 **输出前自检第 4 条**（要求回看连续同类的那几行）。这两条是批量版的补偿机制，删掉就等于放弃一致性。

代价仍然存在：`role` 和 `evidence` 的填写质量通常比单条调用低一档。所以复核时优先看 `role` 是「主语」和「主语中心语」的那批，这批是误判最集中的地方。
