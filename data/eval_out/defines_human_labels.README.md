# 人工盲标说明：`defines_human_labels.csv`

这批表用于回答一个到目前为止**没人真正回答过**的问题：`DEFINES` 边的精确率到底是多少。

之前所有「精度」数字都不是人工标的：

* `data/eval_out/defines_selfcheck.json` 是把建边正则再跑一遍，只能说代码与规则一致；
* `data/eval_out/defines_blind_review.json` 是 LLM 盲判（63%），与规则不同源，但仍然是模型，
  换个提示词能从 27% 掉到 63%，所以它只能当**下界参考**，不能当精度。

## 怎么来的

`scripts/audit_defines.py --mode blind --sample 100 --seed 20261030` 抽出的 100 条 `DEFINES`，
逐条导出为「概念名 + 条文标识 + 条文标题」。抽样前已刻意删除：

* `kind`：LLM 判的「定义式 / 正面规制 / 顺带提及」；
* `cue` / `matched_alias` / `offset`：规则命中位置，看到「cue=normative:应当」就等于被提示了答案。

所以表里只有 5 列，**没有任何一列暗示该边成立与否**。请先去
`data/extracted/articles.jsonl` 按 `article_id` 取 `content` 全文再判——
只看 `citation` 标题是不够的。

## 怎么填

| 列 | 填什么 |
| --- | --- |
| `concept_name` | 概念名，**不要改** |
| `article_id` | 条文 id，**不要改** |
| `citation` | 条文标题，**不要改** |
| `human_label` | `1` = 成立；`0` = 不成立；`?` = 拿不准 |
| `note` | `0` 或 `?` 时**必填**：一句话说明理由；`1` 可留空 |

判「成立」只有两种情形（与 B7 口径一致，别自己加严）：

1. **定义**：条文给出该概念的内涵、外延或构成，如「X 是指……」「X 是……的合同」；
2. **正面规制**：概念（或它的别名）位于条文某个分句的**主语位置**，条文直接规定它
   「应当 / 不得 / 可以 / 有权 / 必须」做什么，或直接规定它的范围、效力。

判「不成立」的典型：概念只作动词宾语（订立 / 解除 / 变更 X）、只在介词短语里（对 X、
关于 X）、只在并列列举里、只用于举例或背景说明，条文真正规范的是别的主体或别的事项。

例：
* 「承揽人交付的工作成果不符合质量要求的，定作人可以合理选择请求承揽人承担修理……」对「定作人」→ `1`（分句主语位规制）
* 「订立借款合同，借款人应当按照贷款人的要求提供与借款有关的业务活动和财务状况的真实情况」对「借款合同」→ `0`（「借款合同」是「订立」的宾语）

## 注意事项

* **不要**回头去看 `mentions_typed.jsonl` 里这条边的 `edge_type` / `cue`，那会污染盲标；
* 拿不准就用 `?` 并写理由——`?` 的数量本身是有信息的（说明判据在边界上不稳）；
* 100 条**都要填**，留空按未标处理，不要跳行；
* 填完不要改列名、不要加列，脚本按固定列名读。

## 标完之后

人工精度 = `human_label == 1` 的条数 / 100，并单列 `?` 的条数（`?` 不计入分母，也不要
把它们悄悄算成 0）。这份数字才是可以写进 README 的「定义级精度」；
`defines_blind_review.json` 的 63% 只能作为对照。

文件编码 UTF-8、无 BOM，行尾 LF；Excel 直接双击可能显示乱码，请用
`数据 → 从文本/CSV → 编码选 UTF-8` 打开，或用 pandas 读。
